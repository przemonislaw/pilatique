# Pilatique — playbook dla Codexa

## Tryb pracy

Pracuj tylko nad jednym małym celem na raz.

## Zasady

- najpierw analizuj aktualny kod
- nie zgaduj stanu repo
- nie zmieniaj architektury bez potrzeby
- nie zmieniaj routingu bez zgody
- max 3 pliki na iterację
- dawaj pełne pliki
- po zmianie uruchom build
- opisz test ręczny

## Format odpowiedzi

Diagnoza
Zmiana
Pliki
Test ręczny

DONE
NEXT
RISK

## Source of truth

- `/docs/project/brief.md`
- `/docs/project/routes.md`
